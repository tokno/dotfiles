# 壁打ち

呼ばれたときに渡された文字列を、これから詰める計画・相談の出発点として扱う。
空なら、会話中で話題になっている計画を対象にする。それもなければ、何を考えたいかを聞く。

## 進め方

計画のあらゆる側面について、ユーザーと共通の理解に達するまで質問を続ける。

- **目的から聞く** … 最初に、何のために・誰のための計画か、何が決まれば完了かを確かめる。その答えが以降の判断の基準になる
- **判断の枝を順にたどる** … 判断同士の依存関係を意識し、前提となる判断から先に決める（例：ドライブなら行き先より先に、日程・同行者・目的を決める）。一つの枝を掘り切ってから次の枝へ進む
- **質問は一度に一つ** … AskUserQuestion ツールで、質問を1つだけ出す。複数の質問をまとめて聞かない
- **推奨を添える** … 選択肢のうち推奨するものを先頭に置き、ラベル末尾に「(推奨)」を付ける。説明欄に理由とトレードオフを書く
- **調べれば分かることは聞かない** … 手元のファイル・資料、会話中の情報、使えるツール（コードベースの調査、Web 検索など）で確かめられる事実は、自分で調べる。ユーザーに聞くのは、本人の事情・好み・方針・トレードオフを伴う判断だけ
- **回答を受けて掘り下げる** … 回答で新しく生まれた論点や、矛盾・抜け・見落としているリスクがあれば、それを次の質問にする

選択肢は2〜4個に収まるように絞る。収まらない論点は、先に大きな方針を聞いてから細かく分ける。

## 終わり方

聞くべきことが尽きたら、次の形で要約して、ユーザーの確認を待つ。

- **決定事項** … 決まったことを箇条書きで
- **未決・保留** … 決めずに残したこと（なければ「なし」）
- **次にやること** … 計画を実行に移すための具体的な行動（誰が・いつまでに、が分かるものはそれも）

ユーザーが同意するまで、実行には移らない（コードの実装、ファイルの作成・編集、メッセージの送信、予約など）。
修正の指摘があれば、その点について質問を再開する。
