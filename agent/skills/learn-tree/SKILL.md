# 木で学ぶ

呼ばれたときに渡された文字列を、学ぶ主題として扱う。
空なら、会話中で話題になっている事柄を主題にする。それもなければ、何を学びたいかを聞く。

## 木の形

- **根** … 主題を理解するための土台になる基礎概念。3〜5個に絞る
- **子** … 親の概念を支える構成要素。子をすべて理解すると、親が腑に落ちる
- **葉** … 本人がすでに理解しているノード。それより下は掘らない

木は最初に全部作らない。本人の理解に合わせて、対話の中で伸ばしたり刈ったりする。

## 進め方

### 1. 目的と場面を聞く

何のために、どんな場面で使いたいかを、一つの質問にまとめて聞く（例：同じ「投資信託」でも、自分で選んで買いたいのか、業界に就職したいのかで根が変わる。「大会を運営したい」なら、何の大会かまで分かると具体例を本人の場面に合わせられる）。
依頼文に目的と場面が書いてあれば聞かない。片方だけ書いてあれば、足りない方だけ聞く。予備知識はここでは聞かず、各ノードで確かめる。

同じメッセージで、確認問題の重さを選べることを添える（「確認問題は軽め・ふつう・しっかりから選べます。途中で変えてもかまいません」）。返事がなければ軽めで進める。

### 2. 仮の地図を見せる

目的に合わせて根を選び、各根の1段下の子までを組み立てて、木として表示する。子はまだ仮のもので、進めながら増減すると添える。
続けて、根それぞれを1〜2文で説明する。

木を組む前に「既知の記録」のファイル一覧を見て、記録にある概念と意味が重なりそうなノードを探す。名前の一致ではなく意味で照合し（「分散投資」と「リスク分散」のような揺れを吸収する）、重なりそうなものだけファイルを開いて説明を読み、本当に同じ概念か確かめる。重なるノードには印を付けて見せ、葉にするかは本人が決める。印は記録の状態で分ける。

- `◇` … 検証済み（例：`◇ 分散投資（投資信託で理解済み・2026-11-16）`）
- `◇?` … 自己申告（例：`◇? 相関（投資信託で自己申告・2026-11-16）`）

本人が葉にしたノードは `✓` にして、それより下は掘らない。本人が掘ると言えば、印は外して普通のノードとして扱う。

掘る順番を提案する。他の根の前提になる根を先に並べる。
本人は、順番を変える、根を足す・削る、知っている根を外す、ことができる。本人が「知っている」と言って外した根は、自己申告として記録に書く。

### 3. ノードを深さ優先でたどる

根を一つ選び、そのノードから次の手順を繰り返す。

1. **理解度を測る** … ノードに入ったら、まず理解度を測る質問を1つ出す（「〇〇を自分の言葉で説明すると？」など）
2. **答えに応じて分ける**
   - 説明できた → そのノードと下の枝を完了にして、次のノードへ
   - 一部だけ説明できた → 足りない構成要素を子として（なければ作って）、その子だけを掘る
   - 分からない → 説明してから、確認問題を出す
3. **確認問題で判定する** … 説明のあとに、自由記述の確認問題を出す（「自分の言葉で言うと？」「この場合どうなる？」）。答えを見て Claude が判定する
   - 理解できている → 完了にして次へ
   - 誤答 → 足りない構成要素が特定できれば、子ノードを作って降りる。特定できなければ、別の角度（例え・具体例・図解）から説明し直す
4. **親に戻って結ぶ** … 子をすべて終えたら親に戻り、子同士をつなげて親を理解できたか、確認問題で確かめる。子の答えの中で、すでに子同士をつなげて説明できていれば省略してよい。省略するときは、その旨を一言添える。本人が飛ばしたいと言えば飛ばす
5. **記録に書く** … ノードが完了するたびに、そのノードを「既知の記録」に書く。説明できた・確認問題を通った・親に戻って結べた、のいずれも検証済みとして書く。本人が「知っているから飛ばす」と言ったノードは自己申告として書く。深さに関係なく、完了したノードはすべて書く。書き込みは黙って行い、対話では触れない

一つの根を掘り切ってから次の根へ進む。本人が「次へ」と言えば、判定を待たずに次のノードへ進む。理由を言わずに「次へ」で飛ばしたノードは記録に書かない（「知っている」と言ったときだけ自己申告として書く）。

### 確認問題の重さ

本人が選んだ重さに合わせて、理解度を測る質問と確認問題を作る。途中で「軽くして」「数字を小さく」などと言われたら、その時点から切り替える。

- **軽め**（既定） … 一言か一文で答えられる問題。「自分の言葉で言うと？」「この場合どちらになる？」など
- **ふつう** … 数文で答える問題や、小さな具体例に当てはめる問題
- **しっかり** … 計算や手順を書かせる問題、複数のルールを組み合わせる問題

どの重さでも、次を守る。

- 計算を含む問題は、暗算できる小さい数で作る
- 人数・成績・履歴などの状態を持つ設問は、出す前に前提が矛盾しないか確かめる（例：不戦勝で1勝した人が「0勝」になっていないか）

### 質問を受けたとき

- **今のノードについての質問** … 答えてから、今のノードの続きに戻る
- **今のノードから外れた質問**（別の根や、木にない話題） … その場で簡潔に答えて今のノードに戻るか、その話題へ移るかを本人に聞く。戻る場合でも、後で掘る価値があれば該当する場所にノードを足す

## 木の表示

次の節目に、現在地付きのテキストの木を出す。毎ターンは出さない。

- 仮の地図を見せるとき
- ノードを足したり刈ったりしたとき
- 根を一つ掘り終えたとき

記号は `✓` 完了、`▶` 現在、`・` 未着手。仮の地図では、既知の記録と重なるノードに `◇`（検証済み）か `◇?`（自己申告）を付け、本人が葉にしたら `✓` に変える。例：

```
投資信託（目的：自分で選んで買いたい）
├─ ✓ 分散投資
│   ├─ ✓ リスクとリターン
│   └─ ✓ 相関
├─ ▶ 手数料
│   ├─ ▶ 信託報酬
│   └─ ・ 購入時手数料
└─ ・ 複利
    ├─ ・ 利率
    └─ ・ 再投資
```

## 既知の記録

主題をまたいで「理解済みの概念」を蓄積するファイル。次の主題で同じ概念を重ねて掘らないために使う。木そのものや現在地は保存しない。

### 場所

`$XDG_DATA_HOME/learn-tree/knowledge/` の下に、概念 1 つにつき 1 ファイル。`XDG_DATA_HOME` が未設定なら `~/.local/share/learn-tree/knowledge/`。
ディレクトリがなければ、最初の書き込み時に作る。

wiki のように概念ごとに分けるのは、照合のときに読む量を抑えるため。一覧（ファイル名）だけで候補を絞り、本文は候補のファイルしか開かない。主題ごとに分けると、照合は結局すべてを読むことになり、同じ概念をどのファイルで更新するかも曖昧になるので、そうしない。

### 形式

ファイル名は `<概念名>.md`。概念名は主題に依存しない一般的な名前にする（「投資信託の手数料」ではなく「信託報酬」）。`/` と空白は使わない（必要なら `_` にする）。

```
# 分散投資

- 説明: 値動きの異なる資産に分けて、全体の振れ幅を抑えること
- 状態: 検証済み
- 主題: 投資信託
- 日付: 2026-11-16
```

- **説明** … 一文。後の主題で意味を照合するための手がかりなので、本人の答えの要点を Claude が一文にまとめる
- **状態** … `検証済み`（Claude が判定して完了にした）か `自己申告`（本人が「知っている」と言った）
- **主題** … 学んだときの主題。複数なら `、` で並べる
- **日付** … 最後に書いた日

他の概念へのリンクや、木の構造は持たせない。各ファイルは独立している。

### 更新の規則

- 書く前に一覧を見て、同じ概念のファイルが既にあるかを意味で照合する（名前が違っても意味が同じなら同じ概念）。あれば新しいファイルを作らず、そのファイルを更新する
  - 状態は `自己申告` → `検証済み` にだけ上げる。`検証済み` を `自己申告` に戻さない
  - 主題が違えば、主題に追記する
  - 日付は更新日にする
- 新しい概念なら、ファイルを作る
- 古い記録は消さず、期限も設けない。日付を見せて本人が判断する

## 話し方

- 一度に扱うのは一つのノードだけ。説明は短く区切り、長い講義にしない
- 理解度を測る質問と確認問題は、通常のテキストで1つずつ出す。選択式にしない
- 本人の目的に結びつく具体例を優先する

## 終わり方

すべての根を掘り終えたら、または本人が終えると言ったら、次をまとめて表示する。

- **最終的な木** … 完了・未着手が分かる形で
- **学んだ要点** … 根ごとに、要点を1〜3行で
- **残ったところ** … 飛ばしたノードや、足したまま掘らなかったノード（なければ「なし」）

木と進捗はファイルに保存しない。保存するのは「既知の記録」に書いた概念だけで、ノード完了のたびに書き終えているので、終わり方でまとめて書くことはしない。
